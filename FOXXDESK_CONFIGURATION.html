FoxxDesk · resilient upstream workflow

Configure o brand sem transformar cada update em uma quebra.

Uma camada central para nome, servidor, relay, chave, ícone, opções de build e CI — preservando o source upstream e aplicando somente mudanças cirúrgicas.

01 · Arquitetura

Uma fonte de verdade, várias plataformas

A pasta .foxxdesk fica fora dos arquivos que normalmente são sobrescritos por uma atualização. O preparador lê essa camada e reaplica somente o necessário.

1. ConfigValida JSON e sincroniza compatibilidade.
2. UpstreamResolve hbb_common da mesma release.
3. Brand + IconPatches textuais + assets gerados.
4. ValidateBloqueia build inconsistente.
Regra principalNenhum arquivo de código é substituído por uma cópia antiga. O rebrand procura padrões e altera trechos específicos; imagens de aplicativo são regeneradas a partir do master atual.
02 · foxxdesk.config.json

Configuração central editável

Edite .foxxdesk/foxxdesk.config.json. O antigo brand.json é apenas uma ponte de compatibilidade e é sincronizado automaticamente.

brand

Identidade pública

display_name, empresa, mantenedor, e-mail, homepage e copyright.

network

Infraestrutura

server, relay e chave pública do hbbs.

icons

Imagem mestre

Fonte, qualidade, padding, descoberta por nome, iOS background e política de atualização.

build / actions

Compilação

Flutter, hwcodec, VRAM, portable, Unix clipboard, ScreenCaptureKit e CI.

CampoO que fazNível

brand.slugNome interno do crate/binário. O padrão é foxxdesk.avançado

03 · Ícones

Seu ícone passa a ser o padrão obrigatório

A fonte oficial é .foxxdesk/assets/icon.png. O prepare aplica o ícone automaticamente, sem depender de --apply-icon-assets.

best

Qualidade máxima

Mínimo 1024 px, recomendado 2048 px, Lanczos, PNG lossless otimizado, proporção preservada e sem crop.

discovery

Busca por nome com escopo

Encontra launcher, AppIcon, ICO e ICNS mesmo se a árvore mudar, mas somente em diretórios de plataforma permitidos.

PlataformaComo é tratado
Androidic_launcher* por densidade; ic_stat_logo.png vira branco + alpha conforme o uso de notification icon.
iOSAppIcon é gerado em RGB com fundo configurável; sem transparência dependente.
WindowsICO multi-resolução com tamanhos de 16 a 256 px.
macOSICNS gerado a partir da fonte 1024+.
SVG existentePreserva width, height e viewBox; troca somente o payload visual.
ProteçãoA descoberta não procura qualquer arquivo chamado icon.png no projeto. Isso evitaria trocar ícones de toolbar, status e componentes que não são o ícone do aplicativo.
04 · Rebrand

Patch-only continua sendo a regra

O perfil full reaplica a allowlist depois de uma atualização. scan_all=false e remove_old_renamed=false mantêm a estratégia conservadora.

python scripts/foxxdesk_prepare.py --target . --dry-run
python scripts/foxxdesk_prepare.py --target . --apply --yes --sync-deps
Nome público ≠ identificador internoVocê pode trocar display_name sem renomear automaticamente FFI, package names, bundle IDs ou todos os executáveis. Essa separação evita regressões desnecessárias.

07 · GitHub Actions

Preflight primeiro, matriz depois

foxxdesk-build.yml roda o preflight em push/PR. A build completa ocorre no workflow_dispatch, evitando gastar a matriz inteira quando o source ainda está inconsistente.

CheckoutSubmodules recursive.
PrepareConfig + Pillow + hbb + brand + icon.
ValidateFalha cedo.
BuildMatriz Flutter reutilizável.
Por que não aplicar todas as flags do JSON na matriz?Porque uma opção válida em Windows pode ser inválida em ARM, Android ou macOS. O workflow mantém a matriz upstream-safe; o wrapper local é onde as opções de build.py são aplicadas automaticamente.
08 · Atualização

Procedimento recomendado

# 1. copie a nova versão upstream

# 2. veja o que mudaria
python scripts/foxxdesk_prepare.py --target . --dry-run

# 3. aplique e sincronize a dependência compatível
python scripts/foxxdesk_prepare.py --target . --apply --yes --sync-deps

# 4. valide
python scripts/foxxdesk_validate.py --target .

# 5. revise
git diff --stat
git diff

# 6. commit / push e compile em Actions
Teste de idempotênciaRode o prepare novamente. O cenário ideal é o segundo passe retornar zero mudanças. Se continuar alterando o mesmo arquivo, existe uma regra não idempotente que deve ser corrigida antes do CI.

10 · Comandos

Cheat sheet

# validar configuração
python scripts/foxxdesk_config.py --target . --sync-legacy

# dry-run completo
python scripts/foxxdesk_prepare.py --target . --dry-run

# aplicar atualização
python scripts/foxxdesk_prepare.py --target . --apply --yes --sync-deps

# ícones somente
python scripts/apply_foxxdesk_icon.py --target . --apply --yes

# preflight
python scripts/foxxdesk_validate.py --target .

# build local: mostrar comando
python scripts/foxxdesk_build.py --target . --dry-run

# build local: preparar + compilar
python scripts/foxxdesk_build.py --target . --prepare
11 · Dicas

Configuração recomendada para estabilidade

Ícone 2048×2048

Evita upscale e dá folga para macOS, iOS e assets futuros.

Slug estável

Troque o nome visível, não o identificador interno sem uma migração planejada.

Pin de dependência

Nova release deve usar o hbb_common daquela release, nunca a branch main isolada.

Segundo passe = 0

Use idempotência como teste de qualidade do rebrand.
