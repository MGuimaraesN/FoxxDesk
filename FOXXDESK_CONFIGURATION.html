Ordem do prepare

config → hooks CI → hbb_common compatível → rebrand runtime → ícones → estado/hash → validate → build
Regra: arquivos de código não são substituídos por snapshots antigos. O rebrand altera somente trechos conhecidos. Arquivos upstream renomeados são preservados, exceto o RustDesk.wxs quando o FoxxDesk.wxs já existe, pois o WiX compila os dois e gera IDs duplicados.

Correção do erro do GitHub Actions

ERRO: Fonte ausente: .../.foxxdesk/assets/icon.png

O v2 não aceita qualquer fallback. Se o master estiver ausente, testa os caminhos de icons.fallback_sources e compara o SHA-256 com .foxxdesk/icon-state.json. Só uma imagem já conhecida como FoxxDesk pode recriar o master.

Proteção: se res/icon.png tiver sido sobrescrito pelo upstream e o hash não bater, o build falha. Ele não aplica silenciosamente o logo errado.
git add .gitignore .gitattributes .foxxdesk scripts .github
git ls-files .foxxdesk/assets/icon.png
# se não aparecer:
git add -f .foxxdesk/assets/icon.png .foxxdesk/icon-state.json

JSON central

O antigo .foxxdesk/brand.json deixou de ser requisito. Se ainda existir, apenas campos vazios podem ser migrados uma vez; depois edite somente o arquivo central.

SeçãoFunção
brandnome público, slug, empresa, mantenedor e homepage
networkserver, relay e chave pública hbbs
iconsfonte, qualidade, descoberta, fallback e iOS
rebrandperfil, scan, cleanup e proteções
upstreamRustDesk ref e pins de hbb_common

Slug: mantenha foxxdesk. Para mudar identificadores internos é necessário habilitar explicitamente allow_internal_slug_change.

Ícones · perfil best

A fonte atual 1024×1024 atende a configuração recomendada. O perfil best usa Lanczos, preserva proporção, não recorta a arte e grava PNG lossless com otimização.

hbb_common

O source e o hbb_common precisam ser da mesma linha. Para RustDesk 1.4.9 o pin é:

7e1c392c62d39c364127307cd408421dd5f8cfb0

O sincronizador nunca baixa a branch main de forma independente.

GitHub Actions

O composite action instala Pillow>=10,<13 e chama o prepare em modo CI. Cada job que faz checkout recebe o mesmo processo antes de compilar.

uses: ./.github/actions/prepare-foxxdesk

O preflight usa o JSON central e o perfil runtime; a matriz completa do FoxxDesk continua sendo disparada via workflow_dispatch.

Comandos

# atualizar/preparar
python3 scripts/foxxdesk_prepare.py --target . --apply --yes --sync-deps

# validar
python3 scripts/foxxdesk_validate.py --target .

# simular
python3 scripts/foxxdesk_prepare.py --target . --dry-run

# build resolvido sem executar
python3 scripts/foxxdesk_build.py --target . --dry-run

# preparar + build local
python3 scripts/foxxdesk_build.py --target . --prepare

Argumentos principais: --ci, --bootstrap, --force-sync-deps, --profile safe|runtime|full, --skip-icons e --skip-validate.
